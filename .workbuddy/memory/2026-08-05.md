- 修复抖音开发者工具中点击侧边栏报 "Delegate to an instance method cannot have null 'this'" 的问题。
- 根因：TT.NavigateToScene 在 WebGL/IL2CPP 下对 lambda 回调的委托编排出问题，容易被 GC 或混淆后元数据丢失。
- 修改文件：
  - Assets/AdSDK/Scripts/cebian.cs
  - Assets/general/SideBar.cs
  - Assets/AdSDK/Scripts/TikTokPlatform.cs
- 方案：将 lambda 回调改为命名实例方法，并在 Awake/Start 中缓存委托引用，避免运行时动态生成委托目标丢失。
- 后续：广告调用同样报该异常，继续修复了激励视频、插屏广告、重访引导等 TTSDK 回调。

- 运行时点击广告报错“广告平台实例未初始化”。
- 根因：TikTokPlatform 构造函数中直接调用 Login/CreateRewardedVideoAd/CreateInterstitialAd，若 SDK 未就绪会抛异常，导致 new 失败，platFormIns 为 null；同时 AdManager.Start 也可能因场景切换未执行。
- 修复：
  - 将 TikTokPlatform 构造函数中的 SDK 调用拆到独立的 Init() 方法，并由 AdManager 延迟一帧调用；即使 Init 失败也先把 platFormIns 赋值，保证后续广告接口可用。
  - AdManager 在 Awake 中启动延迟初始化协程，并在所有广告/侧边栏/分享接口调用前通过 EnsurePlatformInitialized() 重试初始化。
  - 将 TikTokPlatform 中 Login、GetUserInfo、ShareAppMessage、SendOpenIdLog、SendConversionRequest 等异步回调的 lambda 全部改为命名实例方法 + 缓存委托。
- 更新文件：
  - Assets/AdSDK/Scripts/AdManager.cs
  - Assets/AdSDK/Scripts/TikTokPlatform.cs

## UI 资源包体压缩
- 用户反馈打包包体太大，要求压缩 UI 资源。
- 资源扫描（analyze_build_heavy_assets / analyze_ui_resources）：
  - 图片共 576 张 31.85 MB，其中 Resources/ 下 464 张 27.97 MB（Backgrounds/Shapes/Characters）。
  - 字体 9.97 MB（general/UIFont：汉仪蝶语体简1.TTF 3.32MB、汉仪蝶语体简.TTF 3.32MB 疑似重复、Font_JCY.ttf 1.94MB、本墨陈黑.TTF 1.34MB）。
- 根因：UI 图的 .meta 中 WebGL 平台 crunchedCompression=0（未开 Crunch），且 508/552 张图尺寸非 4 的倍数，导致 DXT/Crunch 静默失效、回退未压缩 RGBA32，包体暴涨。
- 处理：写 D:\Unity\haidaofangyu (2)\Temp\optimize_ui.py，对 Resources/NewUI/general 下 552 张 PNG 做：
  1) 补齐宽高到 4 的倍数（对称透明边，偏移≤2px）；
  2) 对应 .png.meta 的 crunchedCompression 全部改为 1。
- 备份目录：D:\Unity\haidaofangyu (2)\Temp\Backup_UIOptimize_20260805_190052（Temp 下 Unity 不进包）。
- 后续：用户需回 Unity 重新 Build（重导入后新 Import Settings 才生效）；Resources 目录整体进首包，未使用图建议移出；字体 9.97MB 可进一步用 SDF 精简/子集化 ttf 优化（暂未做，风险较高）。
